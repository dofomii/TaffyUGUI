# 2. Audit closure summary

The earlier readiness audit identified six blocking/high-priority areas. All six now have explicit resolutions.

## Finding 1 — Taffy baseline

**CLOSED.**

Decision:

```text
Taffy = 0.13.0 exact pin
```

The crate enables the intended Taffy layout capabilities needed by the v1 plan: Flexbox, Grid, Block, Float, Calc, content size, detailed layout info, and TaffyTree.

Dependency upgrades are now explicit changes protected by the lockfile and regression gates.

## Finding 2 — native CI failures

**CLOSED for the Phase 0 bootstrap source.**

The original failures were corrected:

- canonical rustfmt output applied;
- unsafe bootstrap FFI exports now have `# Safety` documentation;
- CI was upgraded to the pinned Rust toolchain and an MSRV lane;
- a full Linux/Windows/macOS + Rust 1.82 run has passed with Taffy 0.13.0.

CI remains a permanent phase gate. Later native tests are added as implementation progresses; the current bootstrap test suite intentionally has little/no feature coverage yet.

## Finding 3 — missing Cargo.lock

**CLOSED.**

`native/Cargo.lock` is committed from the successfully resolved Taffy 0.13.0 build graph.

CI uses `--locked` for Clippy, tests, release builds, and MSRV checks.

---

## Finding 4 — ABI freeze timing

**CLOSED.**

There are now two separate gates:

```text
native ABI candidate
    ↓
native verification
    ↓
ABI-v1-RC
    ↓
cross-platform native compilation/staging
    ↓
minimal managed P/Invoke conformance
    ↓
final ABI v1 freeze
    ↓
rebuild + reverify + restage every native artifact
```

The current bootstrap ABI is version `0`, preventing accidental claims that the current scaffold is ABI v1.

This preserves native-first development while ensuring final ABI v1 is proven through the managed boundary before becoming permanent.

---

## Finding 5 — Unity/toolchain baseline

**CLOSED.**

Primary baseline:

```text
Unity 2021.3 LTS
```

Compatibility policy:

- secondary Unity 2022.3 LTS;
- selected Unity 6 forward lane;
- Unity 2019.4 only as a later evidence-based backward investigation.

Platform build baselines are explicit:

- Windows x64 MSVC first;
- Android ARM64 first, Unity 2021.3-compatible NDK r21d (`21.3.6528147`);
- iOS ARM64/iOS 12+ primary runtime target;
- WebGL built with Unity 2021.3 bundled/matched Emscripten 2.0.19;
- macOS Apple Silicon and retained Intel support validated according to the published compatibility matrix.

Generic newest NDK/Emscripten builds are not accepted as Unity compatibility proof.

---

## Finding 6 — remaining architecture/package ambiguities

**CLOSED.**

Final decisions:

- context handles: generation-safe opaque `uint64`;
- node/resource handles: generation-safe opaque `uint64`;
- ABI array counts: fixed-width `uint32`, not `usize`/`UIntPtr`;
- public C header: generated by cbindgen at `include/taffy_ugui.h`;
- expected errors: stable status codes + last-error diagnostics;
- panic policy: no unwind across C; recover unexpected panic only where target unwind support is deliberately validated; no false promise on abort-only targets;
- global release profile is not forced to `panic = abort`;
- Grid v1 scope explicitly includes justify/align items/self plus named lines/areas;
- Block/FlowRoot/Float and typed Calc are explicit native v1 scope;
- production `TaffyLayoutGroup` must report its own min/preferred/flexible layout input via Unity layout APIs;
- canonical build entry point: `build/build.py`;
- old shell platform commands are non-authoritative and generic WebGL cross-compilation is deliberately disabled;
- `dist/` is generated/ignored;
- verified `UnityPackage/Plugins` native payload is committed for tagged UPM Git installs;
- Unity package explicitly declares `com.unity.ugui` dependency;
- TMP remains an optional adapter rather than a mandatory core dependency.

# 4. Current source assessment

The current Rust and Unity code is intentionally bootstrap code.

The native scaffold still contains temporary implementation choices such as a raw context pointer and a Flex-only style struct. These are **not unresolved design decisions**: Phase 1/2 tasks explicitly replace them with the finalized context registry, generation handles, full Taffy style/resource representation, fixed-width ABI, bulk transfer, errors, versioning, and generated header.

The current Unity scaffold still rebuilds more aggressively than the production design and lacks the final managed wrapper/lifecycle/measurement systems. It remains intentionally paused until the native/ABI gates allow managed conformance and then user-facing feature work.

Therefore these scaffold limitations are implementation backlog, not architecture ambiguity.

# 5. Build-system readiness

The authoritative interface now exists at:

```text
build/build.py
```

Phase 0 provides host quality/build behavior. Later target commands are reserved behind the same interface and intentionally fail with an explanatory message until their implementation phase.

The old `scripts/build-native.sh` delegates host builds to the canonical driver and refuses the old generic macOS/iOS/WebGL bootstrap target paths that could be mistaken for production Unity-compatible builds.

This is deliberate fail-closed behavior.
